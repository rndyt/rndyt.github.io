我们可以大致将整个电商交易流程分解为下单、支付、回调三个部分。

# 订单创建

在订单创建阶段，需要首先保证的是一次逻辑下单操作只会创建一笔订单，也就是订单创建需要具有幂等性，防止因为用户多次点击、网络波动等导致的重复请求产生重复订单。

实现这一能力，首先就需要能够唯一地标识业务请求，也就是为每次业务操作分配一个唯一的幂等键，同时引入数据库唯一约束，确保数据库层面上不可能出现重复订单。

但是对于电商这类高并发系统，如果所有请求都直接进入数据库执行幂等检查和订单创建，可能增加数据库连接、事务竞争和重复查询开销，因此可以使用 Redis 作为前置并发控制层。通过 Redis 的 SETNX 命令，只有成功获得了 Redis 锁的请求才可以进行订单创建的操作，降低数据库压力。在引入 Redis 后，就会出现一个新的问题，如果线程获取 Redis 锁后，还没有完成业务操作就因为异常导致退出该怎么办？

解决方案是锁超时释放+持久化订单状态，Redis 锁都是具有 TTL 的，当锁被释放后，其他线程就可以获取到处理资格。当订单创建涉及多个独立事务或跨服务操作时，单纯依靠 Redis 锁无法保证业务流程的完整执行。系统需要持久化关键业务状态，使后续请求或恢复任务能够识别已完成的操作，并继续推进未完成的流程。
